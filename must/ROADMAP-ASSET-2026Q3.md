## ASSET:roadmap 2026-09-28 09:51 ▸ EmailPin delivery fixed at the root after a fix that never worked; SMTP acceptance is now logged; ERD generated from Prisma's own schema data

Shipped since the 2026-09-07 log.

(1) **EmailPin delivery is fixed at the root.** Commit `d75b29b` found that the 2026-07-17 fix (`family: 4` on the nodemailer transport) never worked. nodemailer's `smtp-connection` ignores that option; it only copies host, port, timeout and localAddress. So since mid-July, PIN emails had been failing with `EHOSTUNREACH` whenever DNS returned an IPv6 address first, because the Mac Mini host has no outbound IPv6 route.

   `d75b29b` added `dns.setDefaultResultOrder("ipv4first")`. That alone still failed for a real user, and `3c7572d` explained why: Node 20's Happy Eyeballs (`autoSelectFamily`) looks up both address types itself and tries them in parallel, whatever the sort order. The final fix sets `net.setDefaultAutoSelectFamily(false)` together with `ipv4first`, before any socket opens (`src/index.ts:1-19`). It was checked live against the affected user (Gmail replied "250 OK", no `EHOSTUNREACH`). The commit reports `tsc --noEmit` clean and vitest 13/13 passing. The dead `family: 4` option was removed from `src/modules/email/register.ts`.

   This matters because signup verification, forgot-password, email change and account deletion all send an EmailPin.

(2) **Sends can now be traced.** `sendPinEmail` now logs `messageId` and the SMTP response when a send succeeds (`src/modules/email/register.ts`). Before, the fire-and-forget `issuePin` call only logged failures. A support ticket saying "the code never arrived" can now be matched to a concrete record that Gmail accepted the message. The code comment notes this is not proof of inbox delivery, since SPF/DKIM/DMARC and spam filtering happen later.

(3) **Google/Apple accounts can request an EmailPin** (`e117fa3`, `src/domains/auth/register.ts:268-292`). This fills in email-ownership proof for accounts that never set a password, using the existing endpoints without new routes. It comes with 3 new tests (Google request, Apple resend, and no PIN sent to an already-verified OAuth account). The paired ISSUE log explains how this also opens a PIN sign-in path.

(4) **Schema documentation can be regenerated.** `scripts/generate-erd.ts` (`npm run erd`, `153dc28`) builds `docs/ERD.md` as a Mermaid `erDiagram` directly from `Prisma.dmmf`, with no extra schema-parser dependency. Relationship cardinality comes from each field's `isRequired`/`isList`, and only key fields (PK/FK/UK) are shown. It covers all 20 models, including the `Property`/`Preference` matching tables and the two separate review models (`RecipeReview` and `Review`), and GitHub renders it natively.

(5) **Earlier assets are still live:** the `matchUsers`/`matchLists` self-join matching, tier setup through `getTier(user)`, admin visibility and the report moderation queue, App Store/Play Store connections, the recipe provider/style enums, the `Preference` model with 65 countries, bookmarks, public username/QR profiles, the metrics and digest pipeline, and the store observability suite.

Roadmap items still open are listed in the paired ISSUE log.
